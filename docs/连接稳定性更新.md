# 连接稳定性更新（2026-10-22）

本次针对手机端与 PC 插件的连接处理进行修复，包名仍为 `com.dsh.remote`。

## 修复内容

- PC 桥接不再等待整个文本响应结束后才压缩发送。SSE / NDJSON 直接逐块转发，普通 JSON / 文本使用流式 gzip，减少首包等待与内存占用。
- GET / HEAD 可在连接失败后重新发现端口并重试一次。POST、上传及带请求体的请求不自动重放，避免断线后重复执行操作。
- 同时失败的请求共用一次端口发现；插件守护和 Tailscale 发布过程避免并发重复启动。
- WebSocket 增加握手超时与双向错误、关闭处理；手机取消 HTTP 请求后释放对应上游连接。
- Android VPN 维护仍可用的物理网络集合，避免旧 Wi-Fi 的丢失事件清空新移动网络。
- 本地资源转发在更换目标时重新绑定；旧线程不能关闭新监听器。增加握手超时，停止时清理已有连接。
- 手机页面加载失败使用约 2 / 4 / 8 / 16 / 30 秒退避（另加少量随机延迟），遵守自动重连开关，手动重连立即执行。
- 去重页面轮询，退出 Activity 后注销网络监听和定时任务；发现结果在主线程更新。
- 不再根据聊天正文中的「请重试」「连接异常」自动点击或刷新。实时会话仍使用工作台自身的重连机制。
- 手机 fetch 仅重试只读请求，不重放写入或取消的请求。不再以缓存 API JSON 冒充成功响应；普通 WebView 缓存保留。

## 应用更新

1. 在 `dsh-phone-remote` 或本仓库的 `pc-plugin` 目录运行 `install.bat`，然后重启 dsh。
2. 手机覆盖安装重新构建的 APK：`D:\AI workspace\dsh-phone-app\build\DSHRemote.apk`。
3. 此 APK 沿用现有签名密钥。原 APK 备份在同目录 `DSHRemote.before-stability.apk`。

源码改动已同步到独立工作目录和本仓库。未自动重启正在使用的 dsh。

## 已完成验证

在 `pc-plugin` 下运行 `node --test connection.test.cjs`：

- SSE 在上游结束前到达手机侧，不被 gzip 缓冲。
- gzip 增量发送且 JSON 内容完整。
- 取消流式请求后释放上游连接。
- POST 被接收后连接重置，不重复提交。
- GET 失败后可切换到新发现端口。
- 并发端口发现共用一次扫描。
- WebSocket 上游重置后关闭手机侧连接。
- 手机 fetch 的只读重试、写入不重试及取消行为。

8 项测试通过。Android 资源、Java、DEX、APK 构建成功，APK v2 / v3 签名校验通过。

## 仍需真机验收

最初构建时无 ADB 连接设备，以下行为尚未做完整端到端验证：

1. 流式输出时从 Wi-Fi 切至移动网络，再切回；观察是否恢复和有无误刷新。
2. 飞行模式保持 30 秒后恢复；确认重试间隔递增，网络恢复后重新连接。
3. 关闭自动重连，制造主页面加载失败；确认保持错误提示，点「立即重连」可恢复。
4. 发送消息或执行命令后立即断网，确认没有重复提交。
5. 反复切换 DSHgo / ZCode go、进入设置和返回；确认资源通道可重新建立。
6. 重启电脑 dsh，使工作台端口改变，确认手机恢复。

这些测试验证代码级故障处理，不能替代真实运营商网络、Tailscale 中继与手机后台策略下的长期运行测试。

## 三星测试机补充

被 Android 以 `ERR_CLEARTEXT_NOT_PERMITTED` 拦截。增加网络安全配置，
仅允许 `127.0.0.1` / `localhost` 的 HTTP / WebSocket，用于 App 本机转发；
远程连接仍使用 TLS，其他明文目标维持禁用。

该连接属于 inspector 通道，尚不能据此认定它是图片故障的原因。
图片查看由用户亲自验收，未将图片功能标记为通过。
排查时使用的临时调试构建已恢复为正式构建配置。
